# にこまる美容室 ホームページ

Hair & Beauty Salon にこまる美容室の公式ホームページです。
素のHTML/CSS/JavaScriptのみで作られた1ページ構成のサイトで、ビルド作業は不要です。そのままGitHub Pagesなどで公開できます。

- 物販用シート: https://docs.google.com/spreadsheets/d/1tUm9vcwxFQcmePR6c52iKO0d6asNkS28m19FpAoTXGs/edit
- 店舗情報用シート: https://docs.google.com/spreadsheets/d/18XFhut26DxMbK4YUnTcoa2FV4pW5U-bembK3WdokPdo/edit
- スタッフ紹介用シート: https://docs.google.com/spreadsheets/d/1tT4duASTJzG3G8KtR0s5cxJbaK10KS79YgGdAB428K8/edit
- **サイト文言用シート(新規)**: https://docs.google.com/spreadsheets/d/1IjNnNu_x-DFAX7rIdQ1b1vLGnSqPq-KTk7DQKBHbFDE/edit

すでにお使いのGoogleアカウントに作成済みです。上4つは共有設定も済んでいますが、**「サイト文言用シート」だけ、以下の共有設定を1回行ってください**(新しく作ったばかりのため)。

1. 上のリンクからシートを開く
2. 右上の「共有」ボタンをクリック
3. 「全般的なアクセス」を「制限付き」→「**リンクを知っている全員**」に変更
4. 権限は「**閲覧者**」のままでOK
5. 「完了」をクリック

これを行わないと、そのシートだけ反映されません(他のシートやサイトの表示には影響しません)。設定後は「Actions」タブから手動実行(下記)するとすぐに反映できます。

### 仕組みについて(なぜ反映に少し時間がかかるか)

以前は「サイトを見た人のブラウザが、その場でGoogleに直接読みに行く」方式でしたが、ネットワーク環境によって読み込みに失敗することがあったため、**より安定した方式に変更しました**。

- スプレッドシートを編集する
- → GitHubの自動処理(GitHub Actions)が、**30分ごとに**スプレッドシートの内容を読み取り、`data/menu.json` などのファイルに変換して自動的にサイトへコミットします
- → サイトはそのファイルを表示するだけなので、訪問者の通信環境に左右されず安定して表示されます

**すぐに反映させたい場合**は、30分待たずに手動で実行できます。

1. GitHubのリポジトリページで「**Actions**」タブを開く
2. 左側の「Googleスプレッドシートをサイトに反映」をクリック
3. 右側の「Run workflow」ボタン →「Run workflow」を押す
4. 1分ほどで実行が完了し(緑のチェックマークが付きます)、サイトに反映されます

⚠️ もし実行結果が赤い✕になり、ログに `Permission denied` のようなエラーが出ている場合は、次を確認してください。
- 「Settings」→「Actions」→「General」→ 一番下の「Workflow permissions」で
  「**Read and write permissions**」を選択して保存してください(初期設定では読み取り専用になっていることがあります)。

### 別のスプレッドシートに切り替えたい場合

`scripts/sync-sheets.mjs` の中にある `SHEETS` の各URLを、新しいスプレッドシートのURLに書き換えてコミット・pushしてください。`data/*.json` を直接手で編集しても、次回の自動反映(30分後、または手動実行時)で上書きされてしまうので編集しないでください。

## ネット予約システム(Firebase連携)のセットアップ

お客様がサイトから直接「予約リクエスト」を送信できる仕組みです。Google製の無料クラウドサービス
**Firebase**を使って、お客様の個人情報(お名前・電話番号など)を安全に管理します。

### この仕組みの安全設計について

- お客様(ログインしていない人)が**できるのは「新しい予約を送信すること」だけ**です。他のお客様の予約内容を見ることはできません。
- 予約の一覧を見たり、内容を確認・変更・削除したりできるのは、**あらかじめ登録したスタッフアカウントでログインした人だけ**です(`/admin/` ページ)。
- 上記のルールは `firestore.rules` に書かれており、Firebase側のサーバーで強制されます。サイトのJavaScriptを書き換えても回避できません。
- `js/firebase-config.js` に書く接続情報(APIキーなど)は、ブラウザから見える場所に置いても問題ない情報です(Firebaseの仕組み上そういう設計になっています)。実際の安全性は上記のセキュリティルールが担保します。
- ⚠️ `/admin/` のURLはお客様向けページからはリンクしていませんが、URLを直接入力すればログイン画面自体は誰でも開けます(ログインできなければデータは一切見えません)。**スタッフのログインパスワードは、他のサービスと使い回さず、推測されにくいものにしてください。**
- 現時点では「二重予約の自動チェック」は行いません。お客様からのリクエストを受けて、スタッフが空き状況を確認したうえで手動で確定する運用です。

### 設定手順

#### ステップ1: Firebaseプロジェクトを作成する

1. https://console.firebase.google.com/ にアクセスし、普段お使いのGoogleアカウントでログイン
2. 「プロジェクトを作成」→ プロジェクト名を入力(例: `nicomaru-biyousitu`)
3. Googleアナリティクスの設定は「オフ」のままで問題ありません → 「プロジェクトを作成」

#### ステップ2: Firestore Database(予約データの保存先)を有効にする

1. 左メニュー「構築」→「Firestore Database」→「データベースの作成」
2. ロケーションは `asia-northeast1`(東京)を選択(変更できないので注意)
3. 「本番環境モードで開始」を選択して作成(ルールはこの後のステップ3で置き換えます)

#### ステップ3: セキュリティルールを設定する(最重要)

1. 「Firestore Database」→「ルール」タブを開く
2. このリポジトリの `firestore.rules` の中身を**全選択してコピー**し、画面のルール欄に貼り付けて上書き
3. 「公開」をクリック

#### ステップ4: スタッフのログインアカウントを作る

1. 左メニュー「構築」→「Authentication」→「始める」
2. 「Sign-in method」タブ →「メール/パスワード」を選び、有効にする
3. 「Users」タブ →「ユーザーを追加」→ スタッフのメールアドレスとパスワードを設定
   (これが `/admin/` ページのログインID・パスワードになります。人数分追加できます)

#### ステップ5: サイトとFirebaseを接続する

1. Firebaseコンソール左上の歯車アイコン →「プロジェクトの設定」
2. 「全般」タブを下にスクロール →「マイアプリ」→ `</>` (ウェブ)のアイコンをクリック
3. アプリのニックネームを入力(例: `nicomaru-web`)→「Firebase Hosting」のチェックは**不要**(このサイトはGitHub Pagesで公開するため)→「アプリを登録」
4. 表示された `firebaseConfig` の値(`apiKey`, `authDomain` など6項目)を、`js/firebase-config.js` の対応する場所にそれぞれ貼り付けて保存
5. 変更した `js/firebase-config.js` をGitHubにコミット・pushすれば、サイトに反映されます

#### ステップ6: 動作確認

1. 公開中のサイトの「ネット予約」を開き、テストで1件送信してみる
2. Firebaseコンソール「Firestore Database」→「データ」タブに `bookings` というコレクションができ、送信内容が入っていればOK
3. `https://<ユーザー名>.github.io/<リポジトリ名>/admin/` を開き、ステップ4で作ったアカウントでログイン
4. 手順1で送った予約が一覧に表示され、「確定にする」「削除」などの操作ができればセットアップ完了です

### 今後の強化案(必要に応じて)

- スパム対策をさらに強化したい場合は、Firebaseの「App Check」(reCAPTCHA連携)の導入を検討してください(現時点では簡易的なスパム対策のみ実装しています)。
- スタッフが増えた場合は、ステップ4の「Users」タブから追加できます。退職者のアカウントは同じ画面から削除してください。

### 高度な予約機能(担当者選択・空き枠自動計算)

メニューごとの所要時間を考慮した空き枠表示、担当スタッフ選択・自動割り当て、シフト管理画面、週間スケジュールの色分け・詳細表示を実装しました。

- ✅ 第1段階: メニューの所要時間の初期値、空き枠計算エンジン(`js/availability.js`)の土台
- ✅ **シフト管理画面**(`/admin/shifts.html`): スタッフのシフトはスプレッドシートではなく、この画面からリアルタイムに登録できます(下記参照)。急な休み・時間変更もすぐに反映されます
- ✅ **第2段階: 予約フォームのカレンダー化**: メニュー選択→担当選択(おまかせ可)→空き状況を見ながら日時選択、という形に作り替えました(下記参照)
- ✅ **第3段階: 週間スケジュールの色分け・詳細表示**: 枠の色がメニューのカテゴリ(カット・カラーなど)ごとに変わり、枠をクリックするとお客様の詳細(お名前・電話番号・メニュー・担当・備考)がその場でポップアップ表示され、確定・完了・キャンセル・削除の操作もそこから行えます

#### シフト管理画面の使い方(`/admin/shifts.html`)

1. `/admin/` と同じアカウントでログイン(`/admin/index.html` から「シフト管理へ」でも移動できます)
2. 上部のタブでスタッフを選ぶ
3. フォームで「曜日パターン(毎週くり返し)」か「特定の日だけ(休み・時間変更)」を選び、出勤するか・時間帯を選んで「この内容で登録する」
   - 曜日パターン: 基本の勤務スケジュール(例: 水曜日は10:00〜19:00勤務)
   - 特定の日だけ: 急な休みや、その日だけの時間変更(例: 9/23だけ休み、9/25だけ13:00〜17:00)。**特定の日の設定は、曜日パターンより優先されます**
4. 登録した内容は、フォームの下にすぐ一覧表示されます。一覧の項目をクリックすると、その内容をフォームに呼び出して編集できます

#### 予約フォームの新しい流れ(`yoyaku.html`)

1. **メニューを選択**(スプレッドシートの内容がそのまま表示されます。所要時間の目安も表示されます)
2. **担当スタッフを選択**(「おまかせ」を選ぶと、空いているスタッフの中から自動的に割り当てられます)
3. **空き状況一覧から日時を選択**(前日までの受付。表示されている日時だけが選べます。「空き状況を更新」ボタンで最新の状態を再取得できます)
4. お名前・電話番号などを入力して送信

**二重予約防止について**: 送信時にFirestoreの「トランザクション」という仕組みを使い、選んだ日時が本当にまだ空いているかをその場で再確認してから予約を確定します。もし他のお客様が一瞬早く同じ枠を予約していた場合は、「別の日時をお選びください」という案内が表示されます(担当者を「おまかせ」にしている場合は、別の空いているスタッフに自動的に振り分けられます)。

⚠️ **この機能を使うには、Firestoreのセキュリティルールを再設定する必要があります。** 「booked_slotsコレクション」を追加し、予約データに担当者・所要時間の項目を追加したため、以前貼り付けた内容が古いままだと予約の送信が失敗します。お手数ですが、Firebaseコンソール →「Firestore Database」→「ルール」タブを開き、このリポジトリの最新の `firestore.rules` の中身を**再度コピーして貼り付け直し、「公開」**してください。

## GitHub Pagesで公開する方法

1. GitHubのリポジトリページで「Settings」を開く
2. 左メニューの「Pages」を開く
3. 「Build and deployment」の「Source」を「Deploy from a branch」に設定
4. 「Branch」を `main` / `/ (root)` に設定して「Save」
5. 数分後、`https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます

## ローカルで確認する方法

`index.html` をブラウザ(Chrome など)にドラッグ&ドロップするだけで見た目を確認できます。
